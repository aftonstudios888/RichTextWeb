# Compatibility and implementation boundaries

RichTextWeb 0.3 is an independent portable flow-document engine, reusable editor controls, converters and desktop WebView hosts. The table describes concrete behavior, rather than a percentage estimate of Word/WPF parity. Microsoft's proprietary layout engine and complete native object system are not included.

## Migration approach

Keep FlowDocument at the application boundary. Convert explicitly between structural symbols and UTF-16 offsets when porting WPF position calculations. Use the same engine for toolbar commands, document features, React/MVVM views and native bridge calls. Floating content occupies one atomic object in the main story; its child blocks form a separately editable rich story.

Choose `RichTextPageEditor` for editable finite pages, or `RichTextBox` with continuous view and `EnableVirtualization` for a windowed block surface. A paginated surface must currently materialize its complete flow for browser measurement. All layout paths require representative document/font fixtures when fidelity matters.

Canonical JSON retains RichTextWeb metadata. See [property semantics](WPF-PROPERTY-SYSTEM.md), [floating interchange](FLOATING-FORMATS.md), [review](ENGINE.md), [collaboration](COLLABORATION.md), [controls](CONTROL.md), [formats](FORMATS.md) and [PDF](PDF.md) for API examples and format-specific guarantees.

Public compatibility references include Microsoft's [Flow Document overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/flow-document-overview), [RichTextBox overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/richtextbox) and [TextPointer API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.documents.textpointer). The implementation and repository tests establish the claims above; an exhaustive Word/WPF conformance suite has not been completed.
