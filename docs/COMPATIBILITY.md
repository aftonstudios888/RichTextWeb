# Compatibility and implementation boundaries

RichTextWeb 0.1.0 is an independent implementation of a portable flow model, editing operations, browser control, format converters and migration adapters. The table identifies concrete support; it is not a percentage estimate of Word or WPF parity. No proprietary Word source or original Word test suite was available or ported. Tests in this repository are original behavioral and interoperability tests.

| Area              | Implemented                                                                                                                                                                                                                | Material boundaries                                                                                                                                                                                        |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flow model        | FlowDocument, Section, Paragraph, Run, Span, Bold, Italic, Underline, Hyperlink, LineBreak, lists, tables, cells, columns, images, UI containers; owned typed collections, parent links, properties, events, serialization | Not every System.Windows.Documents overload/interface/member; UI containers carry portable data rather than arbitrary native controls                                                                      |
| .NET patterns     | PascalCase APIs, dependency property registration, local/inherited typography, notifications, disposable event subscriptions, commands, binding modes, converter hooks                                                     | Not the entire WPF property precedence/routed event/dispatcher/template/animation system                                                                                                                   |
| Text positions    | TextPointer, TextRange, TextSelection; UTF-16 offsets, paragraph separators and object atoms                                                                                                                               | WPF's structural symbol positions and pointer rebasing semantics are not reproduced; no binary/API drop-in compatibility                                                                                   |
| Editing           | Selection, insert/delete, grapheme/word deletion, split/join paragraphs, format/property edits, rich fragments, links/images/lists, rectangular table edits, history, transactions, search/replace                         | Snapshot-based edits are O(document size); no virtualized persistent text rope or production-scale history storage; merged-cell row/column operations reject                                               |
| Review            | Comments, bookmarks, generic annotations; offset updates on edits; resolution and history                                                                                                                                  | No complete tracked changes, authorship merge, revision accept/reject, Word comment-thread interoperability or coauthoring service                                                                         |
| Browser input     | beforeinput, selection/caret, clipboard, keyboard commands, tab, read-only, native composition reconciliation                                                                                                              | Browser-driven IME lifecycle is tested with simulated composition events; real IME/device/assistive-technology qualification remains needed                                                                |
| Rendering         | Browser DOM text shaping, typography, bidirectional browser rendering, tables, lists, images, CSS columns, paper-size view, continuous view, browser print                                                                 | No deterministic Word layout engine, exact screen pagination, native floating anchors, text frames, widow/orphan solver, line-grid/kerning parity, embedded equations, drawing engine or GPU text renderer |
| Document layout   | Page size/padding, typography, paragraph properties, column settings, break-before and print layout                                                                                                                        | No complete headers/footers, footnotes/endnotes, fields, TOC/page references, mail merge, advanced section numbering or native print services                                                              |
| Format conversion | JSON/text, safe HTML, GFM Markdown, implemented XAML schema, RTF subset, real DOCX Open XML ZIP import/export                                                                                                              | Format fidelity is bounded; unknown Office parts/features are not retained in opaque form; not a general Office round-trip fidelity guarantee                                                              |
| PDF               | Selectable-text generation, wrapping/pagination, tables, images, supplied Unicode fonts; existing PDF text/image overlays, highlight/cover, page rotate/reorder/delete/import                                              | Flow export has an independent layout; no arbitrary original-content text editing/reflow, OCR, tagging/PDF-UA or certified PDF/A; covers are not secure redaction                                          |
| Frameworks        | Standard custom element API; React 18/19 typed adapter and hooks; MVVM binding; framework-neutral DOM events/properties                                                                                                    | Vue/Angular usage uses their standard custom-element integration rather than separately tested native wrappers                                                                                             |
| Desktop           | Shared C# JSON client and WPF/WinUI WebView2 / Avalonia NativeWebView source transports                                                                                                                                    | These host the JavaScript engine; native C# code was not compiled or device-qualified here and is not a new native rendering control or published NuGet package                                            |
| Distribution      | ESM/CommonJS/declarations/maps, standalone browser bundle, source, sample, CI, npm provenance and release checksums                                                                                                        | Shippable package mechanics do not establish production or full native conformance certification                                                                                                           |

## Migration approach

Keep the canonical FlowDocument model at the application boundary. Port document construction and commands to the corresponding PascalCase APIs, then adapt views through web components/React or the native host bridge. Translate WPF symbols to the engine's plain-text offset conventions explicitly. Use canonical JSON when retaining complete RichTextWeb metadata matters; consult the format documentation before choosing an interchange format.

The browser control uses the host browser's real layout and text input. It does not pretend that one paper-shaped surface equals a complete Word pagination engine. Browser print and direct PDF export are separate output paths and can wrap differently.

## Reference scope

The migration target was checked against Microsoft's public [Flow Document overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/flow-document-overview), [RichTextBox overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/richtextbox), and framework API guidance cited in [INTEGRATION.md](INTEGRATION.md). The implementation claims above are based on repository source and tests, not on an exhaustive external API audit.
