# Hosting and native interop contract

Use interactive WebAssembly or Interactive Server. Static SSR emits hosts/loading content but cannot execute the browser engine. Wait for Ready; components defer JavaScript initialization until OnAfterRenderAsync. Assets resolve relative to the app base URI under `_content/RichTextWeb.Blazor/`; all bundled modules/worker/decoders are local. Supply application fonts explicitly when required.

BrowserModule exposes constructor/invoke/call/get/set/events with native object identity. Returned native functions use InvokeReferenceAsync, CallReferenceAsync, GetReferenceAsync and CallFunctionAsync or can be passed to another native operation. Synchronous native selectors/renderers must stay in JavaScript. BrowserFunction.DotNet is asynchronous and only suitable for promise-compatible APIs. Canceling an interop wait does not preempt arbitrary synchronous native work or independent Server tasks.

Complete DTO/string reads use CallJsonAsync, InvokeJsonAsync and GetJsonAsync. Binary equivalents stream document/image data. The default explicit limit is 64 MiB, configurable for explicit reads through MaximumTransferBytes. SubscribeJsonAsync transfers complete DTO notifications; SubscribeAsync is a bounded diagnostic snapshot of live native graphs. Ordered CallBatchAsync is not an atomic transaction. Wrap application arguments in BrowserValue.Literal when using generic interop so `$fn`-shaped data is not interpreted as executable callbacks; never accept untrusted executable module URLs.

Optional native DOM templates use uniquely identified BrowserTemplate<TItem> and BrowserFunction.RazorTemplate. Register `builder.Services.AddRichTextWebBlazor()` and `builder.RootComponents.RegisterRichTextWebBlazor()` on WASM; Server uses `AddRazorComponents().AddInteractiveServerComponents(options => options.RootComponents.RegisterRichTextWebBlazor())`. These are independent Blazor roots with nested components, callbacks and shadow-DOM input binding, not replacements for the document engine's model. They do not automatically inherit outer cascading values; declare required CascadingValue components inside them and store durable state separately.

Flush debounced editor changes before save/navigation/unmount. Dispose owned resources/modules asynchronously; borrowed editor/document/engine handles should only have their JS reference disposed, not their native owner. ReleaseAsync is for native resources you own. Keep browser sessions and template registries per app/circuit, never shared across Server users. JSON values are copies, unlike native handles.

Source builds require recursive submodule initialization, npm ci/build and `node blazor/build.mjs`; NuGet consumers require neither Node nor Dockyard. CI restores actual nupkg consumers for net8.0/net10.0 into WebAssembly and Server (`/probe/`), testing EditForm fields, full binding, native pagination/formats/PDF, view switching, Unicode/binary streams, native function handles, Razor callbacks and remounting in Chromium. This does not establish all-browser, hybrid WebView or physical-GPU qualification. Native engine compatibility limits remain applicable.

NuGet is independently versioned in Version.props. Version-changing main merges publish after validation with NUGET_API_KEY (NUGET_TOKEN/NUGET_KEY aliases), reject conflicting immutable versions, verify downloaded public package payloads, and attach packages, symbols, samples and checksums to blazor-v* releases.
